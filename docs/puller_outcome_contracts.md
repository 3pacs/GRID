# Five-puller outcome contract

This AF1 source correction covers FullYieldCurvePuller, RepoMarketPuller, FedLiquidityPuller, NYFedPuller and TiingoFundamentalsPuller. It leaves the existing scheduler classifier unchanged; it does not declare all ingestion sources repaired or activate a job.

A successful supported empty provider response is NO_NEW_DATA with explicit zero writes. Tiingo requires a literal successful empty list. FRED requires a supported empty DataFrame with expected date/value columns. None, unsupported shapes, missing fields, KeyError(date), invalid dates/values and observations entirely lost in normalization are failures, not freshness checks. Invalid observations are rejected before a clean result; valid financial values, SQL, observation-date projection and units are retained. Rejection is per observation for FRED: individual unusable observations (FRED "." missing markers, NaT/NaN dates or values, non-finite values) are skipped with a counted WARNING and are never stored as 0, and a series fails only when every observation in a non-empty response is unusable — the same row-level policy ingestion/fred.py already applies.

NY Fed current-quarter forecast extraction is unchanged. Absence of the next-quarter forecast is clean only alongside a usable current-quarter response. No usable forecast columns fails. SOMA requires an observed as-of date, valid par values and a complete Treasury/MBS breakdown; missing categories cannot be fabricated as zero. Explicit observed zero categories remain zero. Treasury operations require a supported list and valid dates/amounts; malformed records cannot disappear into a clean empty result.

BasePuller._insert_raw adds keyword-only return_result=False. The legacy default returns None with identical validation/SQL/parameters. Explicit True returns the exact execute result without acknowledging commit. These five producers opt in and accept only exact nonboolean nonnegative integer rowcounts. Counts are affected rows reported by the driver, not inferred new distinct records or durability proof. A zero affected count can indicate an unchanged check; it does not prove why the driver affected no rows.

Positive counts become visible only after the enclosing transaction context acknowledges completion. Failed execution/unknown count/failed commit returns unknown committed rows (None) after transaction initiation, with an error or failed outcome. Before-transaction fetch/validation failure can report known zero writes. Staged SOMA results are discarded on transaction failure. A failed derived transaction is represented in the returned list rather than omitted; independently committed earlier leaves remain present. Unknown counts do not crash logging or become zero. Shared classifier aggregate counts may describe a known committed prefix; incomplete/failed leaves retain failure or partial coverage, not complete freshness.

The tests execute actual source methods and unchanged scheduler classification via AST projections with inert DataFrame/FRED/HTTP/engine/result/transaction fixtures. Provider decorators and production module initialization are excluded by the projection; real retry timing, SDK/pandas integration, DB commit/durability, services and native workload remain unverified. Financial helper/parser ASTs, SQL expressions and all previous test files are preserved. No config/schema/dependency or paid/provider gate changes are included.

## V2 NY Fed input correction

The nowcast wrapper rejects invalid supplied vintage dates before dropping rows and rejects explicit nonfinite/unsupported supplied forecast cells before the unchanged parser. Genuinely blank/None/NaN next-quarter cells remain absent; zero and finite forecasts remain valid. The selected SOMA total is validated again after the legacy fallback, before transaction or status publication, so NaN, infinities and negative fallback totals cannot become clean zeros or writes. The parser, units, SQL and the other five production files remain unchanged from V1.
